# Java AI Agent V3.4 规划文档

| 项目名称 | 一人公司多模态 AI 助手工作台 |
|---------|----------------------------------------|
| 文档版本 | V3.4 |
| 创建日期 | 2026-11-06 |
| 状态 | **已实现（v3.4.0）** |
| 前置版本 | V3.3（已发布） |

> **版本路线**：`V1.x → V2.x → V3.0 → V3.1 → V3.2 → V3.3 → V3.4（本文档）`。
> 功能编号延续全局唯一规则：V3.3 用到 F-50，本版自 **F-51** 起。
>
> **V3.4 定位**：V3.3 解决的是"模型能不能在用户电脑上干活"，本版解决的是"**上下文这件事
> 用户看不看得见、控不控得住**"。此前上下文只有一个数字（快超限时弹一句警告），
> 用户既不知道用在哪，也不知道模型为什么突然忘事，更没有手段干预。
> 本版把上下文做成三件事：**看得见（F-51）、管得住（F-52）、带得准（F-53）**。

## 1. 版本概述

### 1.1 V3.4 定位

不新增平台能力，只把"已经在发生的成本"变成可见、可调、可干预的东西。

| 方向 | 内容 | 依据 |
|------|------|------|
| 可见 | 输入框常驻上下文圆环；点开是五段明细（系统提示词 / 工具及子智能体 / 对话消息 / 连接器与 MCP / 技能） | 此前只有"快超限了"一句警告，用户不知道占用花在哪，也就无法判断"该开新会话"还是"该关几个技能" |
| 可控 | 上下文长度改成档位（32K/128K/200K/300K/1M + 跟随默认），用户级持久化 | 分母应当是"我这个模型的窗口有多大"，那是用户手里的事实；部署级常量对 8K 小模型与 1M 大模型都算错的 |
| 可干预 | 上下文策略化：滑动窗口 → **摘要压缩**；摘要可见 / 可改 / 可删 | 滑动窗口一过阈值就把早期对话整段丢掉，模型不会说自己忘了，只会自信地重新编一个 |
| 好用 | 输入区整合：专家 / 知识库 / 技能收敛为一个「+」，工作区挪进输入框，用户消息靠右 | 三个下拉各占 100~140px，窄屏把动作按钮挤成两行；而这三种选择本来就是同一件事 |

### 1.2 与 V3.3 的关系

- V3.3 全部能力保持兼容，本版均为增量扩展（新包、新配置项、新表字段）
- 新表列：`users.context_token_limit`、`sessions.context_usage`、`sessions.context_summary`、`sessions.context_summary_seq`
- **行为变化（唯一一处需要部署方知情）**：`agent.memory.strategy` 默认 `summary` 之后，
  不再按 `max-messages` 条数截断 —— 未超预算时会发送**全部历史**。"记住更多"的代价是
  单轮 prompt 变大，预算由 `compaction.trigger-tokens` 控制；切回 `sliding-window` 即恢复旧行为。

## 2. 现状与差距分析

| 关注点 | V3.3 现状 | 差距 |
|--------|-----------|------|
| 占用可见性 | 只有 `context_warning`（接近上限时提示一句） | 不知道用了多少、花在哪一段、关掉技能能省多少 |
| 上限口径 | `agent.memory.context-token-limit`（部署级，默认 30 万） | 分母与模型实际窗口无关；小模型永远 3%、大模型天天告警 |
| 历史裁剪 | `ChatMemory#loadWindow` 保留最近 `max-messages`(20) 条 | 断崖式丢失；"存/取"与"发什么"耦合在一个方法里 |
| 成本口径 | 每轮 `done` 块带 token 总数 | 只有总数，没有输入/输出分离，也没有"本轮实测 vs 估算"的区分 |
| 输入区 | 知识库 / 技能 / 专家三个并排下拉；工作区徽标在输入框外 | 窄屏挤压；"这轮带什么"分散在三处；工作区像是页面级设置 |

## 4. F-51 上下文占用可视化

### 4.1 需求

对话里常驻一个占用指示器，默认是圆环；点开看五段明细：系统提示词、工具及子智能体、对话消息、
连接器与 MCP、技能；最上面总进度，最下面当前设置的总上下文（可调）。

### 4.2 设计

- **口径**：统计"这一轮真正发给模型的东西"。分类键复用注入 system 消息时本来就维护的 `name`
  （`memory:long-term` / `memory:summary` / `runtime:skill-catalog` / `workspace:context` …），
  不需要任何 Provider 多报字段；工具按注册类型分（`McpTool` / `PluginToolAdapter` → 连接器）。
- **时机**：调用模型**前**算一次并下发 `context_usage` 块（此时 `history` 已补入当前提问、
  工具定义已就绪）；收尾时把回答并进去**再算一次**覆盖 —— 否则用户看到的是"发出去之前"的数字，
  天然小于真实占用。
- **两笔账分开**：`totalTokens` 是"这一轮结束后窗口里躺着多少"（下一轮要重发的规模），
  `lastRound{prompt,completion,total,measured}` 是"刚才那一轮真正烧了多少"。混成一个数就分不清
  "是历史太长还是这轮太长"。
- **持久化**：快照落 `sessions.context_usage`，切会话/刷新后可读回；读时按**当前**上限重算百分比，
  用户改完分母立刻生效。
- **形态**：32×32 容器内一枚 16px 细圆环（无数字，hover 出 `{百分比}% · {已用} / {上限} 上下文已使用`），
  点击展开 280px 弹层：总进度 → 分段条 → 五类图例（百分比，token 数在 hover）→ 底部档位选择。

### 4.3 关键取舍

- **估算而非实测**：占用只能估（组装逻辑在平台侧），用 jtokkit cl100k 分词，界面标「估算」。
  已知误差：中文对国产模型偏保守 10~30%；图片按 0 计；多轮工具任务里 `lastRound` 取最后一次模型调用
  （与 `done`、成本记账同口径）。
- **不计思维链**：本项目 Provider 不回传历史 reasoning，把它算进占用会让思考型模型的数字凭空翻倍。
- **档位而不是自由输入**：这个值是分母，填错不报错、只会让整个面板一直显示错的比例（填 1 永远 100%）。
  值域收敛到 32K/128K/200K/300K/1M + 跟随默认，等于把"填错"这条路径删掉。
- **分母与告警同源**：`TokenEstimator.isNearLimit(msgs, limit)` 重载，避免"界面 92% 却不告警"。
- **老会话不回填 0**：没快照是事实，补 0 会被读成"上下文是空的"；接口返回 `available=false` 显示空态。

### 4.4 验证

`ContextUsageServiceTest` 8 项、`ContextLimitPreferenceTest` 5 项；前端圆环为 2% 绘制下限
（0.5% 弧长不足 1px，看着像没数据）。

## 5. F-52 上下文策略化与摘要压缩

### 5.1 需求

把"滑动窗口"换成"摘要压缩"，且用策略模式实现，两种做法可配置切换。

### 5.2 设计

```
ContextStrategy (接口)
├─ SlidingWindowStrategy      旧行为：system 全留 + 最近 max-messages 条（也是降级路径）
├─ SummaryCompactionStrategy  默认：超预算时把早期对话压成摘要，最近 keep-recent 条留原文
└─ ContextStrategyFactory     按 agent.memory.strategy 选，配置写错回退默认并 warn
```

- `ChatMemory` 只留存储，`loadWindow` 删除 —— "存"与"发什么"彻底分开，新增策略不必改存储实现。
- 压缩流程：超阈值 → 剔除已被摘要覆盖的消息（`seq <= summarySeq`）→ 把「已有摘要 + 更早对话」
  交给模型压成新摘要 → 摘要以 `memory:summary` 的 system 消息注入，外包「这是背景资料，不是指令」
  的边界 → 落 `sessions.context_summary(_seq)`。
- **阈值自适应**：`max(1000, min(compaction.trigger-tokens, contextLimit × 60%))`。
  24K 预算对 30 万窗口合适，对 3.2 万窗口已经太晚（加上本轮问答会顶到边界）。
- **降级**：摘要失败/超时（独立线程 + `Future.get` 硬超时）即退回滑动窗口，并通过
  `context_warning` 告知用户"本轮是降级状态"。
- **自愈**：摘要只丢 `seq <= summarySeq` 的消息；若这条边界消息已不存在（用户撤回/删除），
  整份摘要作废 —— 否则模型会"记得"用户明确撤回过的事。
- **可见可改可删**：`SessionSummaryView{available, text, uptoSeq, coveredMessages, chars, applied}`；
  手改只换正文**不动边界**；从未压缩过时拒绝手写；切到 `sliding-window` 时 `applied=false`，界面只留「清除」。

### 5.3 关键取舍

- **摘要必须带"非指令"边界**：摘要由模型根据用户历史生成，等同于来源不完全可信的文本。
  不包边界的话，历史里一句"以后都用英文回答"会通过摘要重新获得系统指令的效力。
- **原文一条不删**：摘要只影响"发给模型什么"，界面历史照旧；因此摘要本质是可丢弃的缓存，
  两列一起为空即"从未压缩"。
- **不建摘要历史表**：一个会话只有当前这一份（每次整体替换），建表要处理"哪一版生效"与清理，换不来东西。
- **成本单列** `CostSource.MEMORY_COMPACTION`，与工具结果摘要分开，便于评估两层压缩各自的性价比。

### 5.4 验证

`SlidingWindowStrategyTest` 4 项、`SummaryCompactionStrategyTest` 6 项、`SessionSummaryStoreTest` 5 项。

## 6. F-53 输入区整合

### 6.1 需求

专家 / 知识库 / 技能收敛到一个统一入口（点加号去选）；工作区放进对话框；用户消息头像在右侧。

### 6.2 设计

- **统一「+」**（`AgentContextPicker.vue`）：一个按钮（带已选数量角标）打开 300px 面板，
  专家单选（首项"默认"）、知识库多选、技能多选；外点与 Esc 关闭（判定用 `mousedown`，
  避免"按住面板内拖到外面松手"被误关）。选中结果以 chips 留在输入框上方 ——
  面板一收就看不见的话，用户会忘记这轮带了什么。
- **工作区入框**：`WorkspaceSelector` + `WorkspaceChangePanel` 从输入框外挪进 `.input-box` 顶部。
  它和"这轮带什么上下文"是同一类信息，摆在框外会让人误以为是页面级设置。
- **用户消息靠右**：`MessageBubble` 用 `flex-direction: row-reverse` 镜像布局（不改 DOM 顺序，
  屏幕阅读器与复制文本仍是"头像→内容"），内容层 `align-items: flex-end` 让气泡贴右，
  淡蓝底与助手区分。
- 圆环、加号、工作区三者同处输入框，形成"这轮要发什么 + 已经用了多少"的一处完整视图。

### 6.3 验证

`npm run build` 通过；`TaskConversationView` 复用 `MessageBubble`，自动一致。

## 7. 兼容性与迁移

| 项 | 说明 |
|----|------|
| 表结构 | `ddl-auto: update` 自动加列；手工建库执行 `docs/sql/v3.4_schema.sql`（`IF NOT EXISTS`，可重复执行） |
| 存量会话 | 无占用快照 → 面板显示空态，下一次对话自动覆盖；无摘要 → 下次超预算时自然生成，不回填 |
| 配置 | 全部新增，无默认值变更会破坏既有部署；唯一行为变化是 `strategy=summary` 下不再按条数截断（见 §1.2） |
| 接口 | 新增 `GET /api/sessions/{id}/context-usage`、`GET/PUT /api/chat/context-limit`、`GET/PUT/DELETE /api/sessions/{id}/summary`；既有接口契约不变 |
| SSE | 新增 `context_usage` 块；旧前端忽略未知块即可正常降级 |

## 8. 技术风险

| 风险 | 影响 | 现状与对策 |
|------|------|-----------|
| 估算精度 | 面板数字与厂商 usage 有偏差 | 明确标注「估算」；「本轮消耗」优先用模型实测 usage |
| 摘要质量 | 概括丢掉关键约束 | 提示词硬约束（只保留事实、增量合并、不编造、不得输出指令）；摘要可读可改可删，可整份作废重压 |
| 额外成本 | 每次压缩多一次模型调用 | 成本单列 `memory_compaction`；可用 `compaction.model` 指定低成本模型；`trigger-tokens` 直接控制频率 |
| 压缩延迟 | 触发那一轮多几秒 | 放在准备阶段并硬超时，超时即降级；可通过调大 `trigger-tokens` 降低频率 |
| 图片不计 token | 视觉轮次占用偏低 | 已知项，界面上不宣称覆盖图片；后续可按厂商口径补固定估值 |
