## 2. 主题①：多租户 SaaS 化（暂不实施，保留配额型）

### 2.1 决策

> **完整多租户 SaaS 化不实施**（2026-09-08）。主线聚焦单租户场景下的配额管控，不做组织/部门隔离、自助开通、计费订阅、租户级数据共享。

### 2.2 实施边界（重点）

> 明确**不做**：
>
> - ❌ 业务实体加 `tenant_id` 维度的完整共享隔离（多成员看同一租户数据）
> - ❌ 租户自助注册、开通、套餐变更的前台流程
> - ❌ 计费 / 订阅 / 账单体系
> - ❌ 租户管理员角色与成员管理后台
>
> 保留并维护：
>
> - ✅ `tenants` 表 + `users.tenant_id`（配额载体）
> - ✅ `TenantService` 配额检查（`checkResourceQuota`，开关 `agent.v3.tenant.enabled`）
> - ✅ 管理端 `/api/tenants/*` 配额管理接口（仅管理员可用）
> - ✅ 数据隔离维持 V2.2 按 userId 过滤，租户不改变现有查询链路

### 2.3 现状核对（已落地）

| 实现 | 说明 | 默认 |
|------|------|------|
| `users.tenant_id` | 用户归属字段（可空，空=平台直属） | — |
| `tenants` 表 | 租户配额字段（plan/max_users/max_agents/max_workflows/max_tokens_month/status） | — |
| `TenantService.checkResourceQuota` | 创建 Agent/工作流前按租户聚合校验 | `agent.v3.tenant.enabled=false` 直通 |
| `TenantService.usage` | 租户资源用量面板 | — |
| `TenantController` | 租户管理 REST（仅管理员） | — |

### 2.4 原规划快照（归档）

> 原设计目标：支持企业租户隔离，每个租户有自己的用户、Agent、工作流、知识库。
> 租户模型 SQL 与隔离策略详见旧版 `docs/07` F-36 章节（已删减，归档于此）：

```sql
CREATE TABLE IF NOT EXISTS tenants (
    id               VARCHAR(64)  PRIMARY KEY,
    name             VARCHAR(255) NOT NULL,
    plan             VARCHAR(32)  NOT NULL DEFAULT 'free',    -- free / pro / enterprise
    max_users        INT          NOT NULL DEFAULT 5,
    max_agents       INT          NOT NULL DEFAULT 10,
    max_workflows    INT          NOT NULL DEFAULT 20,
    max_kb_docs      INT          NOT NULL DEFAULT 100,
    max_tokens_month BIGINT       NOT NULL DEFAULT 1000000,
    status           VARCHAR(16)  NOT NULL DEFAULT 'active',
    created_at       TIMESTAMP    NOT NULL DEFAULT now()
);

-- users 表加 tenant_id
ALTER TABLE users ADD COLUMN tenant_id VARCHAR(64) REFERENCES tenants(id);
```

### 2.5 恢复实施时的建议步骤

1. **数据隔离**：为 `agent_definitions`、`workflow_definitions`、`knowledge_bases`、`sessions` 等业务表增加 `tenant_id` 维度，查询链路升级为「按 userId + tenantId」过滤，支持租户内共享视角。
2. **租户上下文**：扩展 `SecurityContext` 透传 `tenantId`，统一在查询入口注入，避免漏加导致隔离泄漏。
3. **自助开通**：补充租户注册/套餐变更/停用/续费流程与约束。
4. **计费**：接入 billing 子模块（套餐、账单、用量计费）。
5. **角色**：增加 tenant-admin / member 两级租户内角色，纳入 RBAC。
6. **验收**：对照第 2.2 节实施边界验证隔离不泄漏。

## 3. 主题②：语音 STT / TTS（未来开发项，未实装）

### 3.1 决策

> **语音输入（STT）/ 语音输出（TTS）为未来开发项**，早于 V1.1 明确推迟，未纳入主线交付；依赖「对话承载链路」，同属语言对话模块冻结范围。

### 3.2 范围界定

| 类别 | 内容 |
|------|------|
| 语音输入（STT，F-12） | 浏览器录音 → 后端 Whisper/Paraformer 转写 → 文字回填输入框 |
| 语音输出（TTS，F-13） | 助手回复 → 后端 TTS-1/CosyVoice 合成 → 前端播放（支持流式） |

### 3.3 原设计归档

> 详细设计请见 [`docs/04-V1.1规划文档.md`](04-V1.1规划文档.md) §3（STT）/ §4（TTS）与 [`docs/05-语言对话模块（未来可扩展项）.md`](05-语言对话模块（未来可扩展项）.md)；需求源见 [`docs/01-需求文档.md`](01-需求文档.md) F-08。

| 需求编号 | 说明 |
|---------|------|
| F-12 | 语音输入（STT）：录音 → 转写 → 输入框回填；验收含中英文识别 |
| F-13 | 语音输出（TTS）：朗读按钮 → 合成播放；支持音色选择、长文本流式 |

**接口快照（归档）**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/audio/transcribe` | 语音转文字（STT，multipart） |
| POST | `/api/audio/tts` | 文字转语音（TTS，返回音频流） |

**模型选型（归档）**

| 能力 | 默认 | 备选 |
|------|------|------|
| STT | OpenAI Whisper-1 | 阿里 Paraformer（国内低延迟） |
| TTS | OpenAI TTS-1 | 阿里 CosyVoice / 智谱（中文自然） |

### 3.4 恢复实施时的建议步骤

1. **承载链路**：先确认「语言对话模块」（`05` 文档，冻结）是否恢复，语音依附于对话承载链路。
2. **后端**：新增 `AudioController`、`AudioModelProvider`（STT+TTS 抽象）、`OpenAiAudioProvider` / `QwenAudioProvider`。
3. **前端**：对话输入区加录音按钮（STT）、消息气泡加朗读按钮（TTS）与播放控件。
4. **配置**：`agent.features.*` 语音开关 + 语音模型 API Key。

## 4. 主题③：本地模型（F-38 Ollama，降级为未来扩展项）

### 4.1 决策

> **F-38 本地模型支持（Ollama 私有化部署）降级为未来扩展项**（2026-09-08）。代码已具备**基础能力**（模型注册、对话、健康检查、工具调用兼容），但作为私有化部署扩展**不扩大投入、不纳入主线交付规划**，保留现状。

### 4.2 现状核对（已落地）

| 能力 | 说明 | 启用方式 |
|------|------|----------|
| 模型注册 | `/api/models` 列出 `ollama-chat`（标签含「Ollama」） | `langchain4j.ollama.*` 配置 |
| 本地对话 | Ollama 兼容 OpenAI 端点，流式推理 | 切换 `ollama-chat` |
| 健康检查 | `/actuator/health` ollama 组件 UP/DOWN（`OllamaHealthIndicator`） | 内置 |
| 工具调用 | 模型支持 function calling 时可用 | 对话开工具 |

> 关键类：`model/ollama/OllamaChatProvider`、`config/OllamaHealthIndicator`。

### 4.3 原规划要点（归档）

> 原目标：集成 Ollama，支持私有化部署，降低 API 成本。
>
> 要点：
> - 通过 Ollama HTTP API 调用本地模型；
> - 模型配置支持 provider：`dashscope` / `ollama`；
> - 前端模型选择器展示可用本地模型。

```yaml
agent:
  models:
    providers:
      ollama:
        base-url: http://localhost:11434
        models:
          - llama3:8b
          - qwen2:7b
```

### 4.4 恢复/扩展实施时的建议步骤

1. **前端**：模型选择器正式展示本地模型列表（当前仅后端已具备）。
2. **运维**：补齐 Ollama 集群、GPU 调度与多实例部署方案。
3. **性能**：本地模型响应慢场景下确保异步执行 + 流式输出。
4. **验收**：对照 `docs/10-完整测试用例文档.md` §10.3（LM）用例回归。
