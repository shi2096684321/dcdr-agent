## 1. 版本概述

### 1.1 V1.1 定位

V1.1 是 V1.0 的**增量增强版本**，目标是补齐 V1.0 中「预留但未实装」的多模态能力，并新增联网搜索能力以支持实时信息问答：

| 能力 | V1.0 状态 | V1.1 目标 |
|------|----------|----------|
| **语音输入（STT）** | 仅预留需求，未实装 | 浏览器录音 → 转文字 → 自动填入输入框 |
| **语音输出（TTS）** | 仅预留需求，未实装 | 助手回复可一键朗读 |
| **视频生成** | 仅预留 `VideoModelProvider` 接口与创作模式视频子模式 UI 入口 | 接入可灵/Sora，异步生成 + 状态轮询 |
| **联网搜索** | 未规划 | ✅ V1.1 新增，已交付（v1.1.0），代码依附对话链路 |

### 1.2 版本边界

```
V1.0 (已发布)          V1.1 (已发布 v1.1.0)        V2.0 (规划中)
──────────────         ──────────────────         ──────────────
文本/图片/工具          + 视频生成实装               RAG 知识库
对话/创作               + 联网搜索(新增,已交付)      用户认证
单用户                  ⏸️ 语音输入输出(STT/TTS,未来项) 多 Agent 协作
H2 存储                 H2 存储(不变)              PostgreSQL + 向量库
```

V1.1 **不引入**用户认证、RAG 知识库、多 Agent 等 V2.0 范畴能力，保持单用户、轻量部署，确保小版本快速交付。

### 1.3 与 V1.0 的兼容性

| 兼容项 | 说明 |
|--------|------|
| API 兼容 | V1.0 所有 API 保持兼容，V1.1 新增音频/视频 API 及搜索接口 |
| 配置兼容 | V1.0 配置项保留，V1.1 新增 `agent.models.audio`、视频模型配置、`agent.search` 配置 |
| 数据兼容 | 复用 V1.0 表结构，`generations` 表已预留 `type=video`，无需迁移 |
| 功能开关 | 语音/视频/搜索能力可通过配置开关启用/禁用，默认按 API Key 是否配置决定 |

## 3. 语音输入（STT）

### 3.1 功能概述

用户在对话输入区点击「录音」按钮，浏览器采集语音，上传至后端，后端调用语音识别模型转写为文字，回填到输入框（用户可编辑确认后发送），实现「说话即输入」。

### 3.2 详细需求

#### F-12：语音输入

| 需求编号 | F-12-001 |
|---------|----------|
| **需求名称** | 浏览器录音采集 |
| **描述** | 前端通过 MediaRecorder API 采集麦克风音频 |
| **验收标准** | 1. 输入区提供录音按钮，点击开始/停止<br>2. 录音中显示波形/时长指示<br>3. 支持中文、英文<br>4. 单次录音最长 60 秒 |

| 需求编号 | F-12-002 |
|---------|----------|
| **需求名称** | 语音转写（STT） |
| **描述** | 上传音频文件，后端调用 STT 模型转写为文字 |
| **输入** | 音频文件（webm/wav/mp3），单文件 ≤ 25MB |
| **输出** | 转写文本 |
| **验收标准** | 1. `POST /api/audio/transcribe`（multipart）接收音频<br>2. 默认使用 OpenAI Whisper-1，可配置阿里 Paraformer<br>3. 转写结果自动填入输入框，用户可编辑<br>4. 转写失败时提示具体原因 |

### 3.3 STT 流程

```
┌─────────────────────────────────────────────────────────┐
│  用户点击[录音] → MediaRecorder 采集麦克风               │
│        │                                                │
│        ▼                                                │
│  停止录音 → 生成 audio.webm (Blob)                      │
│        │                                                │
│        ▼  POST /api/audio/transcribe (multipart)        │
│  AudioController → AudioModelProvider.transcribe()      │
│        │                                                │
│        ▼  调用 Whisper / Paraformer API                 │
│  外部 STT 服务                                           │
│        │                                                │
│        ▼  返回 { text: "你好，介绍一下你自己" }          │
│  前端将 text 回填输入框（可编辑）→ 用户确认后发送         │
└─────────────────────────────────────────────────────────┘
```

## 4. 语音输出（TTS）

### 4.1 功能概述

助手回复消息旁提供「朗读」按钮，点击后后端将文本合成为语音，前端播放；支持流式合成（边生成边播放）以降低首音延迟。

### 4.2 详细需求

#### F-13：语音输出

| 需求编号 | F-13-001 |
|---------|----------|
| **需求名称** | 文本转语音（TTS） |
| **描述** | 将助手回复文本合成为语音并播放 |
| **输入** | 文本（≤ 4000 字符）、音色（可选） |
| **输出** | 音频流（MP3）或音频文件 URL |
| **验收标准** | 1. 助手消息气泡显示「朗读」按钮<br>2. `POST /api/audio/tts` 接收文本，返回音频流或 URL<br>3. 默认 OpenAI TTS-1，可配置阿里 CosyVoice / 智谱<br>4. 支持音色选择（如 alloy/echo/nova）<br>5. 长文本分段合成，流式播放降低首音延迟 |

### 4.3 TTS 流程

```
┌─────────────────────────────────────────────────────────┐
│  助手回复完成 → 消息气泡显示[朗读]按钮                   │
│        │                                                │
│        ▼  用户点击[朗读]                                │
│  POST /api/audio/tts { text, voice }                    │
│        │                                                │
│        ▼                                                │
│  AudioController → AudioModelProvider.synthesize()      │
│        │                                                │
│        ▼  调用 TTS-1 / CosyVoice API                    │
│  外部 TTS 服务                                           │
│        │                                                │
│        ▼  返回音频流 (audio/mpeg)                        │
│  前端 <audio> 元素播放，显示播放/暂停/进度               │
└─────────────────────────────────────────────────────────┘
```

## 5. 视频生成

### 5.1 功能概述

V1.0 已预留 `VideoModelProvider` 接口与创作模式「🎬视频」子模式 UI 入口，但未实装具体能力。V1.1 接入可灵（Kling）/ Sora 等视频生成模型，采用**异步任务 + 状态轮询**模式（视频生成耗时 30s~数分钟，不适合同步等待）。

### 5.2 详细需求

#### F-14：视频生成

| 需求编号 | F-14-001 |
|---------|----------|
| **需求名称** | 文生视频（异步任务） |
| **描述** | 创作模式视频子模式提交文生视频任务，异步执行 |
| **输入** | prompt（描述）、model（kling-video / sora）、duration（5s/10s）、aspectRatio（16:9/9:16/1:1）、可选首帧参考图 |
| **输出** | 任务记录（id、status、pollUrl） |
| **验收标准** | 1. `POST /api/videos/generate` 提交任务，返回 pending 记录<br>2. `GET /api/videos/{id}/status` 轮询状态（pending/processing/completed/failed）<br>3. 完成后返回 videoUrl，视频保存到 `data/videos/{date}/`<br>4. 复用 `generations` 表（type=video）记录历史<br>5. 失败时记录 error_message 并可重试 |

| 需求编号 | F-14-002 |
|---------|----------|
| **需求名称** | 视频生成进度展示 |
| **描述** | 前端轮询任务状态并展示生成进度 |
| **验收标准** | 1. 提交后预览区进入"阶段式进度"视图：阶段图标 + 状态文案 + 流动进度条 + 三阶段轨道（排队 / 渲染 / 收尾）+「已等待时长」<br>2. 进度条为**纯前端阶段估算**（视频厂商 API 不返回真实进度百分比），不展示"预计剩余时间"，避免与实际耗时偏差误导用户<br>3. 自动轮询（间隔 3s），状态变更时更新 UI：轮询到 `processing` 即把阶段从「排队」推进到「渲染」；`completed` 进度拉满并显示视频，`failed` 报错<br>4. 已等待时长由前端响应式时钟（每秒刷新）驱动，与阶段进度同步流动<br>5. 完成后预览区播放视频，历史缩略图条追加，支持「下载」「查看详情（复现参数）」 |

### 5.3 视频生成流程

```
用户: 创作模式 → 视频子模式 → 输入描述 → [生成]
         │
         ▼  POST /api/videos/generate
┌─────────────────────────────────────────────────┐
│ VideoController → CreativeEngine.submitVideo()  │
│  ├─ 参数校验                                     │
│  ├─ 参考图存储(可选)                             │
│  ├─ 写入 generations 表 (status=pending)         │
│  └─ 异步线程池提交任务 → 返回 { id, pollUrl }    │
└────────────────┬────────────────────────────────┘
                 │ 异步
                 ▼
┌─────────────────────────────────────────────────┐
│ ImageGenerationWorker(视频版)                    │
│  → VideoModelProvider.generate()                 │
│  → 调用 Kling / Sora API (长耗时)                │
│  → 轮询外部任务状态直到完成                       │
│  → 下载视频 → data/videos/{date}/{uuid}.mp4     │
│  → 更新 generations 表 (status=completed)        │
└─────────────────────────────────────────────────┘
                 │
                 ▼  前端 GET /api/videos/{id}/status (3s 轮询)
┌─────────────────────────────────────────────────┐
│ 状态 pending → processing → completed           │
│ 前端阶段式进度: 排队 → 渲染 → 收尾 (纯前端估算)   │
│ 展示「已等待时长」(每秒刷新), 不展示预计剩余        │
│ 完成后返回 videoUrl → 预览区 <video> 播放         │
└─────────────────────────────────────────────────┘
```

### 5.4 模型路由

视频生成复用 `ModelRouter`，按 `model` 名称路由到具体 Provider：

| model 名称 | Provider | 说明 |
|------|------|------|
| `kling-video` | `KlingVideoProvider`（新增） | 快手可灵，国内可用 |
| `sora` | `SoraVideoProvider`（新增，可选） | OpenAI Sora |

## 6. 联网搜索

### 6.1 功能概述

> ✅ **本节（联网搜索）已在 v1.1.0 交付**：其触发与上下文增强建立在 `ChatController` / `Agent` 引擎 / 对话历史之上（对话承载链路设计存档于 [`docs/05-语言对话模块（未来可扩展项）.md`](05-语言对话模块（未来可扩展项）.md)，但联网搜索功能本身随 v1.1.0 发布）。

参考主流网页对话助手（如 ChatGPT 联网、Kimi 探索、智谱联网搜索等），当前项目对话能力仅依赖模型预训练知识，无法回答时效性问题（如「今天有什么新闻」「最新 JDK LTS 版本」「某股票当前股价」）。V1.1 在对话模式中接入联网搜索能力：

- 助手在回答涉及实时信息、最新事件、时效性数据的问题时，可调用搜索引擎获取实时网页结果；
- 将检索到的网页摘要作为上下文喂给 LLM，由 LLM 基于检索结果生成回答；
- 回复中标注引用来源（标题 + URL + 摘要），便于用户溯源。

支持两种触发方式：
1. **自动判断**：LLM 通过 Function Calling 自主决定是否调用搜索工具（默认开启）；
2. **手动开关**：用户在输入区勾选「🌐 联网」开关，强制本次对话启用联网搜索。

### 6.2 详细需求

#### F-15：联网搜索

| 需求编号 | F-15-001 |
|---------|----------|
| **需求名称** | 搜索引擎接入（SearchProvider） |
| **描述** | 抽象 `SearchProvider` 接口，接入第三方搜索 API，返回结构化搜索结果 |
| **输入** | query（关键词）、maxResults（条数，默认 5）、freshness（时效过滤，可选） |
| **输出** | 搜索结果列表（title、url、snippet、source） |
| **验收标准** | 1. 新增 `SearchProvider` 接口（`search(query, opts)`）<br>2. 默认实现 `TavilySearchProvider`（专为 LLM 优化，返回摘要）<br>3. 可选实现 `BingSearchProvider` / `SerpAPISearchProvider`<br>4. 单次返回 ≤ `maxResults` 条，默认 5 条 |

| 需求编号 | F-15-002 |
|---------|----------|
| **需求名称** | 搜索触发与上下文增强 |
| **描述** | Agent 引擎通过 Function Calling 触发搜索，并把结果作为上下文喂给 LLM |
| **输入** | 用户消息、是否强制联网（`webSearch` 参数） |
| **输出** | 增强后的助手回复（含引用来源） |
| **验收标准** | 1. 将 `web_search` 注册为对话工具，LLM 自主决定是否调用<br>2. 用户勾选「🌐 联网」时强制触发搜索<br>3. 检索结果以 system/工具消息形式拼入上下文，不污染用户原消息<br>4. 回复末尾以 Markdown 脚注或列表形式附引用来源（标题 + URL） |

| 需求编号 | F-15-003 |
|---------|----------|
| **需求名称** | 引用来源展示 |
| **描述** | 前端在助手回复下方展示引用来源卡片，可点击跳转 |
| **验收标准** | 1. 助手消息气泡下方渲染「来源」区域，列出引用网页<br>2. 每条来源显示：标题、域名 favicon、URL、摘要（≤ 1 行）<br>3. 点击来源在新标签打开原网页<br>4. 回复正文中的引用标注与「来源」列表序号对应 |

### 6.3 联网搜索流程

```
┌─────────────────────────────────────────────────────────┐
│  用户: "今天有什么科技新闻?"  [🌐联网 ✓]                 │
│        │                                                │
│        ▼  POST /api/chat { message, webSearch: true }   │
│  ChatController → Agent引擎                              │
│        │                                                │
│        ▼  LLM 决策: 需要联网                             │
│  Function Calling → web_search(query)                   │
│        │                                                │
│        ▼                                                │
│  SearchProvider.search()                                │
│  └─ 调用 Tavily / Bing API                             │
│        │                                                │
│        ▼  返回 [{title, url, snippet, source}, ...]     │
│  Agent 引擎拼装上下文:                                   │
│  system: "以下是检索到的实时信息供参考: ..."             │
│        │                                                │
│        ▼  LLM 基于上下文生成回复 + 引用标注              │
│  返回 { reply, sources: [...] }                          │
│        │                                                │
│        ▼  前端渲染回复 + 「来源」卡片列表                 │
└─────────────────────────────────────────────────────────┘
```

### 6.4 搜索引擎路由

复用 `ModelRouter` 思路，按配置 `agent.search.provider` 路由到具体 Provider：

| provider 名称 | Provider 类 | 说明 |
|------|------|------|
| `tavily` | `TavilySearchProvider`（新增，默认） | 专为 LLM 设计，返回干净摘要，API Key 简单 |
| `bing` | `BingSearchProvider`（新增，可选） | 微软 Bing Web Search API，覆盖面广 |
| `serpapi` | `SerpAPISearchProvider`（新增，可选） | Google 结果经 SerpAPI 代理 |

> 默认选用 Tavily：其结果已为 LLM 优化（去除噪声、返回摘要），接入成本最低；用户可按可访问性与配额切换。

### 6.5 上下文与 prompt 策略

- **系统提示词增量**：启用联网时追加 system 段——「你可以调用 web_search 工具获取实时信息。回答时优先使用检索结果，并在句末以 `[1]`、`[2]` 形式标注引用序号，对应末尾来源列表。」
- **检索结果注入**：以工具消息 / system 段形式注入，**不**改写用户原消息，保持对话历史干净。
- **结果裁剪**：每条 snippet 截断 ≤ 500 字符，总上下文 ≤ 4000 tokens，避免超出模型窗口。

## 8. 技术选型（新增）

| 类别 | V1.0 | V1.1 | 选型理由 |
|------|------|------|---------|

## 附录：技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 浏览器录音权限被拒 | STT 不可用 | 前端检测权限并友好引导 |
| Whisper 转写延迟 | 体验差 | 限制单次录音时长；显示转写中状态 |
| TTS 长文本合成慢 | 首音延迟高 | 分段流式合成，边生成边播放 |
| 视频生成耗时长（数分钟） | 用户等待焦虑 | 异步任务 + 进度预估 + 完成通知 |
| 可灵/Sora API 不稳定 | 视频生成失败 | 任务失败可重试；记录 error_message |
| 视频文件体积大 | 存储压力 | 限制时长；生成后可选压缩 |
| 搜索 API 费用/配额超限 | 联网搜索不可用或超额计费 | 限流 + 限制单次结果条数（默认 5） |
| 搜索结果噪声/质量差 | 回答失准 | 默认 Tavily（已为 LLM 优化）+ snippet 裁剪 + LLM 二次筛选 |
| 模型不支持 Function Calling | 无法自主触发搜索 | 关键词规则触发；或强制联网开关下直接搜索拼入上下文 |
| 搜索结果引入错误/过时信息 | 误导用户 | 回复强制标注来源供溯源；提示「以来源页面为准」 |
