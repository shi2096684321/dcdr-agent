## 1. 测试概述

### 1.1 用例编号规则

`TC-<模块>-<序号>`，模块代码：AUTH(认证)、CHAT(对话)、MULTI(多模态)、RAG(知识库)、AGENT(自定义Agent)、WF(工作流)、ROUTE(智能路由)、TRIG(触发层)、EXEC(执行容错)、GOV(治理监控)、MKT(模板市场)、COST(成本配额)、TEN(多租户)、PLG(插件)、LM(本地模型)、PROD(生产化加固)、OPS(运维)。

### 1.2 优先级定义

| 级别 | 含义 | 通过标准 |
|------|------|----------|
| P0 | 核心链路, 阻断发布 | 100% 通过 |
| P1 | 重要功能 | ≥ 95% 通过, 遗留项有规避方案 |
| P2 | 边缘/体验/性能 | 按缺陷等级评估 |

### 1.3 测试环境

| 项 | 要求 |
|----|------|
| JDK | Temurin 21（JAVA_HOME 指向） |
| 数据库 | PostgreSQL + pgvector（profile=pg）, 已执行 docs/sql 全部 schema 脚本 |
| API Key | DASHSCOPE/ZHIPU/DEEPSEEK 有效 key；Ollama 本机 11434（可选） |
| 前端 | npm run build 产物或 dev server |
| 工具 | curl/Postman（API）、浏览器（UI）、Zipkin（追踪）、Prometheus（指标） |

### 1.4 通用前置

- 应用以 `--spring.profiles.active=pg` 启动；
- 存在管理员账号 admin（角色 admin）与普通账号 user1/user2（角色 user）；
- 各 V3 开关（`agent.v3.*`）默认关闭，涉及开关的用例按用例内说明临时开启并重启。
