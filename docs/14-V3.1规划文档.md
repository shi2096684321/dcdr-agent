## 1. 版本概述

### 1.1 V3.1 定位

V3.0 发布后，平台已具备生产级编排能力。V3.1 不追求大而全的新能力堆叠，而是**三收一扩**：

| 方向 | 内容 | 依据 |
|------|------|------|
| 安全收口 | 会话接口越权修复、对话检索归属校验 | V3.0 开放知识库给普通用户后，安全边界需完整闭合（技术债） |
| 体验增强 | 语音输入/输出（STT/TTS） | `docs/12` 存档项②，设计已齐备（F-12/F-13），对话承载链路早已交付，恢复时机成熟 |
| 生态扩展 | 代码执行沙箱、Agent/工作流版本管理、成本分析报表、远程模板市场 | `07-V3.0规划文档.md` §20 远景展望（V3.1 项）+ F-34 收尾 |
| 运维落地 | 多实例 + PostgreSQL 主从 + 灾备演练 | `docs/13-部署与高可用.md` 已有完整方案（F-40.13），本版实施 |

### 1.2 与 V3.0 的关系

- V3.0 全部能力保持兼容，V3.1 仅增量扩展（新 API / 新配置项，默认关闭）
- V3.0 明确"不实施"的事项继续冻结：完整 SaaS 多租户（`docs/12` ①）、本地模型扩大投入（`docs/12` ③）
- 浏览器 Agent / 多模态 Agent 扩展 / Agent 自主学习 维持 V3.2+ 远景，不纳入本版

## 2. 现状与差距分析

| 领域 | V3.0 现状 | V3.1 目标 |
|------|----------|----------|
| 数据安全 | 知识库已按 userId/visibility 隔离；**但会话修改类接口（system-prompt/title/delete）与对话内 RAG 检索尚未做归属校验** | 全部资源访问路径闭合归属校验，越权用例纳入自动化测试 |
| 交互模态 | 纯文本输入 + 图片/文件上传 | 支持语音输入（STT）与语音输出（TTS） |
| Agent 能力边界 | 工具调用限定在平台内置 + MCP | 增加代码执行沙箱（数据分析/计算类任务闭环） |
| 治理 | 监控视图 + 路由日志 + 审计 | 补齐 Agent/工作流版本管理与成本分析报表（F-34 完整收尾） |
| 模板生态 | 本地模板市场（预置模板） | 支持远程官方模板仓库在线安装 |
| 部署形态 | 单实例开发能力 | 多实例 + DB 主从高可用可落地（方案已存档） |

## 4. F-41 安全加固收口

> 背景知识库开放给普通用户（user 角色拥有 kb:read/kb:write）后，部分访问路径的归属校验存在缺口。本项为**安全硬伤修复**，最先交付。

### 4.1 已识别的越权面

| 位置 | 问题 | 修复方式 |
|------|------|---------|
| `SessionController` 修改类接口 | `PATCH /{id}/system-prompt`、`PUT /{id}/title`、`DELETE /{id}` 仅校验存在性（`getSession(id)` 无 userId），任何登录用户可篡改/删除他人会话 | 改用 `sessionManager.getSession(id, userId)` 归属校验，越权统一返回 404 |
| `GET /{id}/messages` 等读取接口 | 部分读取路径未校验归属，存在消息记录越权读取风险 | 同上，统一按 userId 过滤 |
| 对话内 RAG 检索 | `ChatRequest.knowledgeBaseIds` 由前端传入，后端未校验 kbId 归属——用户可传他人 USER 级 kbId 触发检索其私有文档 | 在编排层（`prepareForChat`/检索工具入口）按 `getAccessible` 同口径校验每个 kbId（自己的 USER 级或 PLATFORM 级才放行） |
| 越权回归测试 | 缺少自动化越权用例，修复后易回退 | `docs/10-完整测试用例文档.md` 增加安全用例章节（横向越权矩阵），纳入 CI |

### 4.2 实施要点

1. 归属校验统一收敛到各 Manager/Service 层（与 `KnowledgeBaseService.getAccessible` 同模式），Controller 只做参数传递，避免散点判断
2. 修复遵循"越权即不存在"原则（返回 404 而非 403，避免资源枚举探测）
3. 审计日志记录越权尝试（`audit/` 模块，`record("access_denied", ...)`），为风控提供数据
4. 验收标准：横向越权矩阵用例全绿（用户 A 对用户 B 的会话/知识库/文档做读写删均被拒绝）

## 5. F-42 语音对话（STT/TTS）

> 恢复实施 `docs/12-未来可扩展项记录.md` 存档项②（原 F-12/F-13）。设计、接口、模型选型在 04/05 文档已完备，本版直接按存档设计实施。

### 5.1 范围

| 类别 | 内容 | 编号 |
|------|------|------|
| 语音输入（STT） | 浏览器录音 → 后端转写 → 文字回填输入框 | F-42.1 |
| 语音输出（TTS） | 助手回复 → 合成 → 前端播放（支持流式） | F-42.2 |

### 5.2 实施要点

1. **后端**：新增 `AudioController`（`POST /api/audio/transcribe` / `POST /api/audio/tts`）、`AudioModelProvider` 抽象 + `OpenAiAudioProvider`（Whisper-1 / TTS-1）与 `QwenAudioProvider`（Paraformer / CosyVoice 备选）
2. **前端**：输入区录音按钮（按住说话 / 点击录音）、消息气泡朗读按钮与播放控件
3. **配置**：`agent.audio.*` 开关与模型 Key（默认关闭，按需启用）
4. **计费**：STT/TTS 用量纳入 `CostTracker`（F-39 体系，按音频时长折算 token 口径）
5. **验收**：中英文识别准确、长文本流式合成、语音开关关闭时接口不可见（403/404）

## 6. F-43 代码执行沙箱

> 来源 `07-V3.0规划文档.md` §20 远景展望（代码执行沙箱，V3.1 项）。

### 6.1 范围

- 新增内置工具 `code_interpreter`：模型可生成并执行 Python/JS 代码段，返回 stdout/结果，用于数据计算、格式转换、图表数据生成等任务
- 与现有工具框架一致（`Tool` + `ToolRegistry` 注册期 Schema 转换）

### 6.2 安全设计（本项核心难点）

1. **隔离执行**：容器化沙箱（如独立 Docker 运行时 / gVisor）或进程级沙箱（seccomp + 无网络 + 只读 FS + 资源限额 CPU/内存/时长）
2. **权限控制**：默认关闭（`agent.tools.sandbox.enabled=false`）；仅 admin 可配置启用；自定义 Agent 工具白名单机制复用（`agentAllowedTools`）
3. **输入输出管控**：代码长度与执行时长上限；输出截断入库（复用 `TOOL_RESULT_MAX_LEN` 机制）
4. **审计**：每次执行记录代码摘要 + 耗时 + 退出码，审计日志留痕

### 6.3 里程碑

放 **V3.1-rc**：安全方案需评审通过后再编码，不阻塞 alpha/beta。

## 7. F-44 治理完善（版本管理 + 成本分析）

> F-34 的收尾项。V3.0 已交付监控视图 / 链路追踪 / 审计，本项补齐"版本"与"成本"两块。

### 7.1 版本管理（F-44.1）

- Agent / 工作流定义变更时生成快照版本（`agent_definition_versions` / `workflow_definition_versions`）
- 支持查看历史版本 diff、回滚到指定版本
- 发布到模板市场时强制携带版本号

### 7.2 成本分析报表（F-44.2）

- 基于 `cost_records`（F-39 已落库）按 用户 / 模型 / 时间维度聚合
- 监控视图（MonitorView）新增成本页：日/周/月消耗趋势、Top 用户、模型成本占比
- 支持导出 CSV

## 8. F-45 远程模板市场

> 本地模板市场（V3.0 已交付 TemplateMarketView）的延伸：官方远程模板仓库。

### 8.1 范围

1. **仓库协议**：模板仓库为一个静态 JSON 清单 + 模板包 URL（轻量，无需后端），支持配置多个仓库源
2. **在线安装**：MarketView 增加"远程仓库"页签，浏览 → 安装（下载 → 校验 → 克隆为本地 Agent/工作流）
3. **安全**：模板包签名校验（防篡改）；导入的 Agent 提示词/工具白名单做安全审查提示
4. **配置**：`agent.market.remote-repos[]` 仓库源列表

### 8.2 依赖

- 需先建设官方仓库站点（可先以 Gitee/GitHub 仓库 + Release 附件形式承载，降低建设成本）

## 9. F-46 灾备与高可用落地（F-40.13）

> 按 `docs/13-部署与高可用.md` 已存档方案实施，从"单实例开发"升级为"生产多实例"。

### 9.1 范围

| 项 | 内容 |
|----|------|
| 多实例部署 | 应用无状态化改造确认（会话/内存态检查）+ Nginx/LB 负载均衡 + SSE 长连接粘滞策略 |
| PostgreSQL 高可用 | 主从流复制 + 故障切换（Patroni 或云 RDS）；pgvector 随库复制 |
| 备份恢复 | 每日全量 + WAL 归档；恢复演练脚本（`docs/13` 已给出要点） |
| 定时清理 | `routing_logs` / `audit_logs` 过期数据归档任务（复用定时任务模块） |
| 演练验收 | 灾备演练一次：杀主库 → 自动切换 → 业务恢复 RTO/RPO 达标 |

### 9.2 注意事项

- H2 文件库仅限开发环境，生产强制 PostgreSQL（启动校验）
- `data/` 运行时目录（知识库文档/上传文件）在多实例下需共享存储（NFS/对象存储）——与 V3.0 的 data 入库剔除配合，属部署约束

## 12. 技术风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 沙箱逃逸 | 服务器安全 | 容器隔离 + 无网络 + 资源限额；安全评审前置；默认关闭 |
| 语音服务成本 | API 费用 | 用量入 CostTracker；配额联动；默认关闭按需开启 |
| 多实例 SSE | 长连接负载不均 | LB 粘滞会话 + 优雅停机（V3.0 已具备） |
| 远程模板安全 | 恶意模板 | 包签名校验 + 导入审查提示；仓库源仅 admin 可配 |
