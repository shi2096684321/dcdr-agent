# dcdr-agent 项目自述（供知识库导入）

> 用途：让系统在被问及"你是谁 / 你能干什么 / 这个项目是什么"时，能基于事实回答，
> 而不是靠猜。本文只写已确认的事实，不写规划中的能力、不写未经验证的数字。
> 事实来源：`README.md`、`docs/15-产品定位.md`、`pom.xml`、`docs/sql/*.sql`、实际接口清单。

## 1. 一句话定位

面向个人创业者（一人公司）、自由职业者、独立创作者的 **AI 助手工作台**：
用户像安排员工一样分配任务，平台内部用多个角色分工完成，对外只呈现一个统一入口。

项目名：一人公司多模态 AI 助手工作台（工程名 `dcdr-agent`）。

## 2. 它是什么 / 不是什么

**是什么**

- 一个把「对话、专家（Agent）、知识库（RAG）、工作流编排、长期记忆、成本治理」收进同一界面的工作台。
- 面向单人/小团队，目的是**少在多个 SaaS 之间来回切换**。
- 内部可以有多个 Agent 协作，但**对外永远不出现"Agent 列表"这种复数形态**。

**不是什么**

- 不是 Agent 搭建平台：用户不应该"先配置、再使用"。判断标准是——
  一句话里出现"用户需要先选择 / 配置 / 搭建"，就已经跑偏了。
- 不是通用聊天机器人：差距在于内部的角色分工、工具调用与可治理的执行链路。
- 不是面向所有个人消费者：目标用户是有重复劳动需要外包的人。

## 3. 三类必须守住的边界（防产品漂移）

1. **"一人公司"是用户身份，"员工"只是心智模型**：用户是老板，目标是让他感觉"我有几个人在帮我"，
   而不是"我在管理一个 Agent 列表"。
2. **工作台是干活的地方，不是配置的地方**：正确形态是「一个对话框 + 一排我的员工卡片（点卡片＝派活）」；
   错误形态是「Agent 列表页 → 点进去 → 填 prompt / 选工具 / 调 temperature」。
   C 端铁律：**用户做不了"配置"，只能做"选择"**。
3. **"Agent"对外永远不出现复数**：内部派生多少执行体，用户不感知、也不需要知道。

## 4. 核心能力（已实现）

| 能力 | 说明 | 对应接口前缀 |
|---|---|---|
| 对话 | SSE 流式对话、上下文记忆、多轮会话、停止生成 | `/api/chat` |
| 会话管理 | 增删改查、人设（persona）、消息历史、导出 Markdown/JSON | `/api/sessions` |
| 专家（Agent） | 自定义专家、模板、克隆、版本快照与回滚、版本 diff | `/api/agents` |
| 知识库 (RAG) | 文档上传→分块→向量化→检索；支持用户级与平台级可见性；混合检索（向量+BM25，RRF 融合） | `/api/knowledge-bases` |
| 长期记忆 | 记忆类型/作用域/重要度/常驻注入；关键词触发；归档与恢复；对话内「请记住 X」 | `/api/memories` |
| 工作流 | 步骤式与 DAG 编排、执行、执行历史、断点续跑、人工审批、Webhook 触发、版本回滚 | `/api/workflows` |
| 定时任务 | Cron 调度（Spring 6 字段：秒 分 时 日 月 周） | `/api/scheduled-tasks` |
| 创作 | 图片生成、视频生成、音频 TTS、项目化归集生成物 | `/api/images` `/api/videos` `/api/audio` |
| 智能路由 | LLM 意图识别，自动分发到工作流/Agent，低置信度回退，路由日志可查 | `/api/routing` |
| 运维治理 | 成本统计与报表（CSV）、模型调用统计、调用链（traceId 贯穿）、检索健康度、回答反馈 | `/api/monitor` `/api/llm-calls` `/api/feedback` |
| 管理后台 | 用户管理、租户配额、审计日志、插件与模型管理 | `/api/admin` `/api/tenants` |

## 5. 技术架构（事实）

- **后端**：Java 17 + Spring Boot 3.3.5，Web 层 WebFlux（响应式），SSE 流式输出。
- **AI 框架**：LangChain4j 1.19.0（core）+ 1.19.0-beta29（社区集成，含 DashScope 通义千问）。
- **数据库**：PostgreSQL 16 + pgvector；向量列 `document_chunks.embedding VECTOR(1536)`，
  建 `ivfflat` 余弦索引；共 25 张表（v2.0 / v3.0 / v3.1 三个建库脚本）。
- **缓存与协调**：Redis 7，用于分布式限流计数与定时任务租约锁。
- **联网搜索**：自建 SearXNG（AGPL-3.0、无 API Key），替代第三方 Tavily。
- **代码执行沙箱**：自托管 opensandbox-server；`docker.sock` 只挂给沙箱服务端，业务应用零特权。
- **可观测**：Micrometer Tracing + Zipkin + Prometheus + Actuator。
- **前端**：Vue 3 + Vite 5 + Element Plus + Pinia + ECharts；页面由 `mode` 状态与二级页签驱动，
  **未使用 vue-router**，所以 URL 不会随页面变化。
- **部署**：依赖与应用分开编排 —— `docker-compose.yml` 只含中间件，
  `docker-compose.app.yml` 只含应用，两者经固定网络 `dcdr-net` 互通。

## 6. 关键术语（用户问到时按这个解释）

| 术语 | 含义 |
|---|---|
| 专家 / Agent | 一个带角色设定、绑定模型、可选工具与知识库的执行体。用户视角是"我的员工" |
| 技能 | 可复用的任务模板（如周报撰写、会议纪要、代码评审），可安装到专家上 |
| 知识库 | 文档集合，经分块与向量化后可被检索；分「用户级」与「平台级」 |
| 平台级知识库 | `visibility=PLATFORM` 的库，所有用户的对话都会把它纳入检索候选范围 |
| 长期记忆 | 跨会话保留的结论性信息（偏好/项目/反馈等），按作用域与重要度注入 |
| 工作流 | 多步骤任务编排，支持 DAG、重试退避、审批与断点续跑 |
| 智能路由 | 用户只说一句话，由 LLM 判断该交给哪个专家或工作流 |
| 人设 (persona) | 会话级角色设定，只影响该会话 |

## 7. 权限模型

- `admin`：全部权限，含 `user:manage`（用户/租户管理）与 `model:manage`。
- `user`：对话、会话、知识库、专家、工作流、定时任务。
- `guest`：仅 `chat:chat`。
- 资源级越权统一由 `ownershipGuard` 校验，**越权与不存在都返回"不存在"**，避免资源枚举。
- 空库的**第一个注册用户自动成为 admin**，仓库不预置任何默认账号。

## 8. 常见问答

**Q：你能做什么？**
A：对话、管理会话、创建和调度专家、管理知识库并做检索、编排工作流、维护长期记忆、生成图片视频、
查看成本与调用链。具体能力取决于当前部署是否配置了模型 API Key。

**Q：它和普通聊天机器人有什么区别？**
A：多角色分工、工具调用（联网搜索、代码沙箱、知识库检索）、可治理的执行链路（成本、调用链、限流、审批）。

**Q：为什么它说"不知道"某些实时信息？**
A：模型知识有截止时间；联网搜索依赖 SearXNG 服务可用。

**Q：为什么 `/actuator/health` 显示 DOWN？**
A：健康检查会探测所有启用的远程模型 provider，全部不可达即判 DOWN（不配 Key 或无外网时必然如此），
不代表业务接口不可用。
