### 2.3 回归覆盖到的关键路径

- 未带 Token / 伪造 Token 一律 401；`refresh` 后换发新 Token 可用。
- 首个注册用户自动获得 `admin`（实测 `role=admin`）。
- 会话：创建 → 改名 → 设人设 → 读消息 → 导出 Markdown → 访问不存在的 ID 返回「不存在」。
- 专家：模板列表（6 个内置）→ 创建自定义 → 更新触发版本快照 → 版本列表 → 克隆。
- 知识库：创建 → 上传文档 → 文档列表（回报 `status` / `chunkCount`）。
- 记忆：写入常驻记忆 + 项目记忆 → 列表 → 概览 → 归档 → 恢复。
- 工作流：模板列表（5 个）→ 按模板结构创建（`steps` + `dag`）→ 列表 → 执行历史。
- 定时任务：创建（默认禁用，避免真实触发）+ 列表。
- 管理后台：用户分页、系统概览、审计日志。
- 运维：成本统计、模型用量、调用链、路由日志、检索健康、线程池。
- 负向：越权/不存在统一返回「不存在」而非 403（防资源枚举，符合设计）。

## 三、缺陷与问题清单

| 编号 | 级别 | 现象 | 证据 | 影响 | 建议 |
|---|---|---|---|---|---|
| **DEF-01** | 中 | `POST /api/auth/refresh` 成功后，**旧 Access Token 立即失效**（`TOKEN_REVOKED`） | `AUTH-05`：refresh 后带旧 token 请求 `/api/auth/me` → HTTP 401、`code=401` | 客户端若在后台静默刷新，刷新瞬间正在飞行的请求会 401，前端表现为「偶发掉线/刷新后要重登」 | refresh 只应作废旧 Refresh Token，不应拉黑仍在有效期内的 Access Token；或将「拉黑全部」限定给 logout |
| **DEF-02** | 低（设计一致性） | 业务错误（不存在/越权/校验失败）HTTP 状态恒为 200，错误放在 `body.code` | `SESS-07`：HTTP 200 但 `code=404`；其余 400 同理 | 网关、APM、`curl -f` 无法按状态码判定失败，监控易漏报 | 保留统一 `Result` 包装的同时，至少让 4xx/5xx 语义映射到 HTTP 状态码 |
| **DEF-03** | 高 | 模型上游调用失败时，`POST /api/chat` 仍返回 `code=200`，把 `调用失败: {厂商错误}` 直接写进回答正文 | `CHAT-01`：HTTP 200 / `code=200`，但落库的 assistant 消息正文为 `调用失败: {"error":{"code":"invalid_api_key"...}}` | ①前端把错误当正常回答渲染；②成本与成功率统计把失败计为成功；③用户侧无法区分「模型没答」与「答了这句」 | 上游失败应返回非 2xx 或 `code!=200`；流式场景应发 `error` 事件而非 `chunk` |
| **ENV-01** | 环境 | 未配置有效 `DASHSCOPE_API_KEY`：文档向量化失败（`documents.status=failed`、`chunk_count=0`）、检索返回 500 | `KB-02/KB-03/KB-04`；`documents.error_msg` 为厂商 `invalid_api_key` | 知识库全链路不可用（属外部依赖缺失，非代码缺陷） | 交付环境需注入有效 Key；无 Key 时前端应在文档行显式提示「向量化失败，检查模型 Key」 |
| **ENV-02** | 环境 | 技能市场接口 504（外部 SkillHub 不可达） | `SKILL-02`：`code=504 技能市场暂不可用(网络不可达或超时)` | 技能市场页不可用（内网/代理环境常见） | 保持 504 + 友好提示即可；如需离线可用，应支持本地技能包导入（已有 `/api/skills/import`） |
| **OBS-01** | 低（可观测性） | `/actuator/health` 恒为 DOWN 且无详情 | 实测 HTTP 503 `{"status":"DOWN"}`，单次耗时 ≈3s，与 `LlmProviderHealthIndicator` 的 `timeout(3s)` 吻合 | 外部模型抖动会导致 K8s/LB 摘除整个实例，即使业务接口正常 | 把外部 provider 探测移出主 health（单独 group 或独立端点）；`show-details` 对匿名请求至少给出 `components` 概要 |

> DEF-01 / DEF-02 / DEF-03 均为**本轮回归新发现**，未做修复（不属本次任务范围），已在上表给出定位与改法。

## 六、结论

1. **主干功能可用**：47/51 条接口用例通过，认证、会话、专家、记忆、工作流定义、定时任务、
   管理后台、运维查询等主路径全部正常；392 条单元测试零失败。
2. **需要在 v3.2 修掉的三件事**：DEF-03（对话失败伪装成功，优先级最高）→ DEF-01（刷新掉线）→ DEF-02（状态码语义）。
3. **交付前置条件**：必须注入有效的模型 API Key，否则对话 / 向量化 / 检索 / 多模态四条链路都不可用。
4. **建议补的测试**：Controller 层契约测试（当前 0 覆盖）、登录链路集成测试、
   `mvn verify` 纳入 CI、前端 E2E 冒烟。
