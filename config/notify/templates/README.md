# 推送消息模板

定时任务执行结果推送到企业微信 / 钉钉时使用。**改完立即生效，不需要重启**（每次推送都会重新读文件）。

## 目录结构

```
config/notify/templates/
├── wecom_bot/          # 企业微信群机器人
│   ├── success.md      # 执行成功
│   └── failed.md       # 执行失败
└── dingtalk_bot/       # 钉钉群机器人
    ├── success.md
    └── failed.md
```

删掉某个文件就会回退到代码里的内置默认模板，所以这个目录可以完全不存在。
目录位置由 `agent.notify.templates-dir` 指定（默认 `./config/notify/templates`）。

## 可用变量

| 变量 | 说明 | 示例 |
|---|---|---|
| `{{taskName}}` | 任务名称 | 每日技术晨报 |
| `{{status}}` | 原始状态 | `success` / `failed` |
| `{{statusText}}` | 中文状态 | 执行完成 / 执行失败 |
| `{{time}}` | 执行完成时间 | 2026-10-30 14:35:18 |
| `{{duration}}` | 本次耗时 | 8.4 s / 623 ms / 2 分 5 秒 |
| `{{content}}` | Agent 输出正文（**全文**，已做表格适配） | —— |
| `{{summary}}` | 正文概览，按渠道取前 N 字，在句末/换行处断开 | 今日重点 3 条：… |
| `{{runLink}}` | 指向详情页的整行链接（含 markdown 语法） | [查看完整结果](https://...) |
| `{{error}}` | 失败原因 | LLM 调用超时: connect timed out |

## 概览与详情链接

抓取类任务（读几篇文章、汇总成长文）的输出可能上万字，塞进 IM 既放不下也没人读。
默认模板因此用 `{{summary}}` 而不是 `{{content}}`：

- `{{summary}}` —— 前 N 字，**N 按渠道取值**（见下表），尽量在句号或换行处断开，
  不会出现"……同比增长 12.4%，主要得"这种半句话。
- `{{runLink}}` —— 渲染成 `[查看完整结果](https://.../share/runs/<token>)`。
  详情页免登录、有效期 7 天（`agent.notify.share-ttl-days`），过期返回 404。

### 概览字数按渠道区分

| 渠道 | 概览字数 | 消息上限 | 依据 |
|---|---|---|---|
| `wecom_bot` | **900 字** | 4096 字节 ≈ 1365 汉字 | 给标题/时间/链接留出余量，再大会频繁触发截断、把末尾链接切掉 |
| `dingtalk_bot` | **3000 字** | 18000 字符 | 只占六分之一，够放"要点 + 几条数据"，又不会刷成三屏长文 |

以前两个渠道共用全局 `agent.notify.summary-chars: 300`。这个值只能取两者的交集，
结果钉钉那条 18000 字符的上限几乎闲置 —— 一条 9 列的岗位表格被截到 300 字后只剩表头和半行，
看着像"任务什么都没产出"。现在按渠道分别取值，全局配置退化为兜底（渠道级配 0 才用它）。

**要生成链接必须配 `agent.notify.share-base-url`**，例如 `https://agent.example.com`。
留空时 `{{runLink}}` 渲染成空串，模板里那一行自然消失，只推概览——相对路径在 IM 里点不开，
给个坏链接比不给更糟。

> 详情页不需要登录，**拿到链接的人都能看**（和分享链接同理）。如果输出内容敏感，
> 就把 `share-base-url` 留空，只推概览。

`{{content}}` 仍然可用：不想用概览、想直接塞全文的任务，把模板里的 `{{summary}}` 换成 `{{content}}` 即可。

写错变量名不会报错，也**不会**被替换成空——它会被原样保留在消息里，这样你一眼能看出拼错了。

## 表格会被自动转成列表

**企微和钉钉的群机器人 markdown 都不支持表格。** 直接发 `| 公司 | 岗位 |` 这种内容，
群里看到的就是一堆竖线加 `|---|---|` 分隔行，既占篇幅又没有可读性。
所以推送前会把 Markdown 表格转成：

```
**1. 深圳市衡序云联科技有限公司**
岗位：Java开发工程师（支付方向）｜城市：深圳｜年限要求：3-5年
薪资：15-25K｜核心技术要求：Java高并发/多线程, Redis/Kafka｜发布时间：2026-10-30
投递链接：[链接](https://...)｜内推：未标注
```

规则：

- 表头变成字段名，第一列加粗作标题行，其余列按 `列名：值` 每 3 组换一行
- 纯 URL 的单元格压成 `[链接](url)`，省下的字符够多放一条数据
- 空单元格跳过，不输出空字段名
- 表格外的文字（结论、说明）原样保留，所以"结论 + 表格"能正确混排
- 只有「表头 + 分隔行 + 至少一条数据」才认定是表格，普通带竖线的文本不会被误伤

页面上的任务详情仍然展示原始 Markdown（那里表格能正常渲染），转换只作用于推送。

## 三条注意事项

**1. 用 `{{name}}`，不要用 `${name}`**

`${}` 是 Spring 的占位符语法。虽然模板放在文件里不经过 Spring 解析，但为了不和配置文件里的写法混淆，统一用双花括号。

**2. 不要在多行内容外层套引用块**

企业微信和钉钉的 `>` 引用都是**逐行**生效的。如果写成：

```markdown
> {{content}}
```

而 `content` 是多行文本，只有第一行会带上引用样式，后面的行会"掉出来"变成普通正文，视觉上很割裂。想让正文整体缩进，只能自己保证每行都有 `>`，但那样每段之间会出现空引用行，反而更难看。

**3. 正文里的 markdown 会原样生效**

`{{content}}` 是 Agent 生成的自由文本，里面可能带 `##`、`**`、列表。它们会被渲染，有可能和你模板里的标题层级打架（比如正文里的 `##` 盖过模板标题）。这是刻意不做转义的——转义后正文会变成满屏 `\#\#`，比偶尔的层级错乱更难读。

唯一的例外是**表格**：IM 不支持，会被转成列表（见上一节）。

## 长度限制

| 渠道 | 上限 | 单位 |
|---|---|---|
| `wecom_bot` | 4096 | **字节**（中文 3 字节/字，约 1300 汉字） |
| `dingtalk_bot` | 18000 | **字符** |

超长时优先截断 `{{content}}` 或 `{{error}}`，标题、时间、耗时这些元信息不会被切掉。截断后末尾追加 `…(内容过长, 已截断)`。

**不要把 `{{content}}` 放在消息最前面还指望截断保留尾部**——截断只针对正文本身，如果模板其余部分（比如你自己加的一大段固定说明文字）本身就超过上限，整体会被硬截断。

## 钉钉特有

如果是「自定义关键词」模式，关键词会自动追加到消息末尾，且其长度在渲染前就从预算里扣掉了，不会被截断吃掉。模板里不需要写关键词。
