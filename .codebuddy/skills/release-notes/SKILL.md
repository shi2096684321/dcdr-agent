# Release Notes 发布说明规范（dcdr-agent）

本项目每次发布新版本，**必须**按统一格式产出发布说明，不允许只改文档状态、不生成发布文件。

## 一、触发条件

当发生以下任一情况时，执行本规范：
- 用户发起「发布 vX.Y」「打版本」「生成 Release Notes」等请求；
- 版本规划文档（如 `docs/04-V1.1规划文档.md`）从「规划中」转为「已发布」；
- 用户明确要求统一发布格式。

## 二、文件名与位置

- 发布说明统一存放于项目根目录 `docs/` 下，文件名固定格式：
  - `RELEASE-v<主版本>.<次版本>.<修订号>.md`（例如 `RELEASE-v1.0.0.md`、`RELEASE-v1.1.0.md`）
- 同时在 `docs/` 下保留一份带语义的归档（可选，建议保留）：`docs/0X-V<x.y>发布说明（Release Notes）.md`

## 三、统一内容模板（必须包含以下章节）

以现有 `docs/RELEASE-v1.0.0.md` 为权威模板，新版本须沿用相同结构与风格：

```
# dcdr-agent v<版本号>

一句话定位（基于 Spring Boot + Vue 3 的 Agent 平台……）。

## ✨ 核心特性

按能力域分组列出本版交付内容（对话能力 / 创作能力 / 工具调用 / 多模型适配 / 工程化 等）。
- 每条用 `-` 列举，含简短说明
- 未交付但规划中的能力单独标注（如「语音输入/输出：未来开发项」）

## 📦 技术栈

| 层 | 技术 |
|---|---|
| 后端 | ... |
| 前端 | ... |
| 协议 | ... |

## 🚀 快速开始

（与 v1.0.0 一致的启动命令，仅当本版有变化时更新）

## 📝 说明

本版交付范围总结 + 指向下一版本规划文档（如 V2.0 见 docs/03-...）及冻结/扩展项存档（如对话模块见 docs/05-...）。
```

## 四、内容准确性要求

- 发布说明中的交付项**必须与代码实际状态一致**：
  - 列出「已实现并随版发布」的能力，不夸大、不遗漏。
  - 对「已实现但依附于冻结模块（如对话承载链路）」的能力（如联网搜索依赖对话模块），须明确标注「已交付」并指向对应归档文档。
  - 对「明确推迟的未来开发项」（如语音 STT/TTS），须在特性中标注「未来开发项」。
- 发布前**必须编译验证**：`$env:JAVA_HOME='D:\app\jdk17'; mvn -q -o compile -DskipTests`（或对应命令），确保可构建。

## 五、联动更新（不可遗漏）

发布时除生成 `RELEASE-vX.Y.Z.md`，还需同步：
1. 对应版本规划文档（如 `docs/04-V1.1规划文档.md`）状态改为「已发布」+ 发布日期；
2. `docs/01-需求文档.md` 版本规划表中该版本行状态更新；
3. 相关冻结/扩展存档文档（如 `docs/05-语言对话模块（未来可扩展项）.md`）的范围说明，移除已交付项；
4. 若使用 Git，建议打 `vX.Y.Z` tag（需用户确认后再执行 git 操作）。

## 六、禁止

- 禁止「只改文档状态、不生成发布文件」。
- 禁止把未实现的能力写成已交付。
- 禁止在未编译验证的情况下宣称「可发布」。
