用 Java 文本块写 SQL 的几个坑 - 编程笔记

2026-09-12 · 阅读 872

文本块在 Java 15 定型，用于书写多行字符串。相比拼接加号，它让 SQL、JSON、HTML 片段重新变得可读。但它在缩进和转义上有几处容易踩的地方，下面按踩坑顺序记录。

坑一：缩进由结束分隔符决定

文本块的公共缩进量，取的是"内容行"与"结束分隔符所在行"中较小的缩进。也就是说，把结束的三个引号顶格写，内容里的缩进会被原样保留。

String sql = """
        SELECT id, name
        FROM users
        WHERE created_at > ?
        """;

上面的写法里，结束分隔符与内容行同缩进，因此生成的字符串不含前导空格。如果把结束分隔符往左移，那部分缩进就会进入字符串。

坑二：反斜杠仍然是转义符

文本块并没有关闭转义。写正则时，一个反斜杠仍要写成两个；否则编译期就会报非法转义字符。这一点在从普通字符串粘贴过来时最容易被忽略。

// 正确：文本块里的正则需要双反斜杠
String pattern = """
        ^\\d{4}-\\d{2}-\\d{2}$
        """;

坑三：注释里也不能写非法转义

Java 的词法预解析对注释同样生效。如果在注释里写下一个非法的反斜杠加字母组合，编译会直接失败，而不是把注释忽略掉。这个行为在别的语言里很少见，第一次遇到时很难联想到注释。

  • 文本块不能用于单行短字符串，收益不明显。
  • 拼接变量仍然要用 formatted 或加号。
  • 换行符统一为 LF，不受平台影响。
