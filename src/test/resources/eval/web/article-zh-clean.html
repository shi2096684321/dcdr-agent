工作区与本地文件操作正式上线_技术日报

2026-10-30 10:20 · 技术日报 · 阅读 1204

工作区能力让智能体可以直接读写用户指定的本地目录。此前模型只能把文件内容塞进对话上下文，超过长度上限就被截断，长文档几乎无法处理。接入工作区之后，模型可以按需读取片段、定位后再修改，不再需要一次性把全文塞进提示词。

为什么要有权限档位

允许写入之后，风险面随之扩大。模型可能误删文件，也可能把无关目录纳入范围。为此我们引入三级权限档位，读、写、删除分别授予，默认只读。档位在会话建立时由用户确认，模型无法自己提升，也无法通过参数绕开。

撤回是兜底而不是补救

撤回能力是这套设计的兜底。每次改动都会记录到操作日志，用户可以在界面上按单次操作或按文件回滚，不必依赖版本控制。日志同时保存改动前后的内容快照，因此即使文件没有纳入 Git，也能回到改动前的状态。

需要强调的是，撤回不替代版本控制。它解决的是会话内的一次性误操作，跨度以单次会话为限；跨会话的长期演进仍应交给 Git 之类的工具管理。
